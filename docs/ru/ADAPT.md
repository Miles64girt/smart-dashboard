# Адаптация под своё устройство

Приложение настроено на 600×1024 и на планшет, на котором проверялось. Здесь — как поменять город, часовой пояс, расписание, яркость, список вещей и базовые размеры вёрстки под свой планшет.

> ⚠️ **Проверено только на одном планшете.** Всё, что ниже, проверялось на Huawei MediaPad T3 7 (BG2-U01), Android 7.0. На другом устройстве результат может отличаться — проверяйте по [чек-листу](TESTING.md). Используете на свой риск.

## Где лежит конфиг

Все настройки собраны в одном файле:

```
app/src/ru/home/dashboard/DeviceConfig.java
```

Он появился в версии 1.3 и заменил разбросанные по коду константы. Меняете значения → пересобираете APK ([BUILD.md](BUILD.md)) → ставите на планшет. Из интерфейса настройки не редактируются: приложение не хранит лишних экранов и не усложняет себе жизнь.

> Всё, что описано в этой статье, — это правка Java-файла и пересборка. Если не хотите собирать сами, возьмите готовый APK и попросите нейросеть внести правки по [PROMPT_RU.md](../../PROMPT_RU.md) — но собрать всё равно понадобится.

## Поля `DeviceConfig`

| Поле | По умолчанию | Что делает |
|---|---|---|
| `TIME_ZONE` | `""` | часовой пояс в формате IANA. Пусто — системный пояс планшета |
| `AUTO_LOCATION` | `true` | определять город автоматически по IP через wttr.in |
| `LATITUDE` | `55.7558` | широта, если автоопределение выключено |
| `LONGITUDE` | `37.6173` | долгота, если автоопределение выключено |
| `CITY` | `"Москва"` | подпись города в углу, если автоопределение выключено |
| `DAY_START_HOUR` | `8` | час, когда включается экран и дневная яркость |
| `DAY_END_HOUR` | `21` | час, когда включается ночной режим и экран гаснет |
| `PACKING_HOUR` | `20` | час, когда показывается вечерний список вещей |
| `PACKING_SKIP_SATURDAY` | `true` | не показывать список в субботу |
| `MUTE_SOUND` | `true` | переводить планшет в беззвучный режим при старте |
| `DAY_BRIGHTNESS` | `0.62` | яркость экрана днём, от 0 до 1 |
| `NIGHT_BRIGHTNESS` | `0.02` | яркость экрана ночью, от 0 до 1 |
| `DEFAULT_PACKING_ITEMS` | пусто | стартовые пункты вечернего списка; пусто — список пустой |
| `NOTEBOOK_FROM_CALENDAR` | `false` | добавлять пункт «Тетрадь (предметы из календаря на завтра)» |
| `DESIGN_WIDTH` / `DESIGN_HEIGHT` | `600` / `1024` | базовые размеры макета, под которые считаются все отступы и шрифты |

Поля читаются при старте приложения. Если поменять значение и пересобрать APK, приложение подхватит новое сразу — старые настройки в памяти планшета (отметки списка, кэш погоды) не помешают.

## Город и координаты

### Вариант 1: автоопределение (по умолчанию)

```java
public static final boolean AUTO_LOCATION = true;
```

При старте приложение спрашивает у wttr.in данные без координат и берёт оттуда город, определённый по IP. Ничего настраивать не нужно, но точность зависит от провайдера: иногда вместо города определяется область или ближайший крупный город.

### Вариант 2: вручную

Отключите автоопределение и задайте координаты с названием:

```java
public static final boolean AUTO_LOCATION = false;
public static final double LATITUDE = 59.9343;   // ваш город
public static final double LONGITUDE = 30.3351;
public static final String CITY = "Санкт-Петербург";
```

Как получить координаты: откройте любой картографический сервис, найдите свой город и скопируйте широту с долготой. Четырёх знаков после запятой достаточно — для погоды точнее не нужно.

`CITY` — это только подпись в правом верхнем углу левой половины. На запрос погоды она не влияет: погода берётся по координатам.

## Часовой пояс

```java
public static final String TIME_ZONE = "";                 // системный пояс
public static final String TIME_ZONE = "Europe/Moscow";    // задан явно
```

Пустая строка — самый правильный вариант для обычного планшета: приложение использует системные дату, время и часовой пояс. Явный пояс нужен, если:

- в прошивке сломан или «залип» системный часовой пояс (на тестовом планшете он был GMT и не менялся через ADB);
- вы хотите, чтобы расписание и даты считались по одному поясу независимо от настроек устройства.

Формат — стандартные имена IANA, например `Europe/Moscow`, `Asia/Yekaterinburg`, `Asia/Novosibirsk`, `Asia/Vladivostok`. Полный список — в базе IANA, её знает и сам Android.

> Часовой пояс влияет на всё: дату, день недели, время событий календаря, «сегодня», расписание 08:00/20:00/21:00 и определение дня/ночи. Если панель показывает не то время — почти наверняка дело здесь.

## Расписание

```java
public static final int DAY_START_HOUR = 8;    // экран включается
public static final int DAY_END_HOUR  = 21;    // экран гаснет, ночной режим
public static final int PACKING_HOUR  = 20;    // вечерний список вещей
```

- Часы задаются целыми числами от 0 до 23. Минуты не настраиваются — срабатывание всегда в начале часа.
- `DAY_START_HOUR` должен быть меньше `DAY_END_HOUR`, иначе «день» будет длиться всю ночь.
- Вечерний список показывается раз в день; если вы уже отмечали всё или окно уже открывалось, повторно по расписанию оно не появится.
- Суббота пропускается по умолчанию (`PACKING_SKIP_SATURDAY = true`). Поставьте `false`, если хотите список и в субботу — например, чтобы собирать вещи на воскресную поездку.
- Если сдвигаете расписание, помните: до 21:00 экран горит постоянно, после — гаснет. Для круглосуточной панели (например, в офисе) поставьте `DAY_END_HOUR = 23` и `DAY_START_HOUR = 0` или выключите ночной режим логикой под себя — но учтите риск выгорания экрана, см. [FAQ](FAQ.md#экран-выгорает-что-делать).

## Яркость и звук

```java
public static final float DAY_BRIGHTNESS   = 0.62f;
public static final float NIGHT_BRIGHTNESS = 0.02f;
public static final boolean MUTE_SOUND     = true;
```

- Значения яркости — от `0.0f` до `1.0f`. Это яркость **окна приложения**, системная настройка экрана не меняется.
- Ночью приложение дополнительно затемняет картинку почти в ноль и показывает подпись «касание — включить экран».
- `MUTE_SOUND = true` переводит планшет в беззвучный режим при каждом запуске: приложение не хочет будить дом звуками уведомлений. Если планшет ещё и будильник — поставьте `false`.
- Яркость зависит от привычного освещения: для спальни днём может хватить `0.45f`, для светлой кухни — `0.8f`.

## Список вещей

```java
public static final String[] DEFAULT_PACKING_ITEMS = {};   // пусто — как в релизе
```

Пустой список — значение по умолчанию и правильная настройка для публичного APK: чужих вещей в коде нет. Если хотите, чтобы на новом планшете список сразу был заполнен вашими вещами, перечислите их строками по образцу шаблона в самом файле. Дальше проще добавлять и удалять пункты прямо в приложении кнопкой «+ Добавить свой пункт» и долгим нажатием — это не требует пересборки.

Те же пункты, что вы добавили вручную, сохраняются в настройках приложения и переживают перезагрузку. Но при обновлении APK с удалением данных или при удалении приложения они пропадут.

## «Тетрадь из календаря»

```java
public static final boolean NOTEBOOK_FROM_CALENDAR = false;
```

Если включить, в вечерний список добавляется пункт «Тетрадь (…)», а в скобках — предметы из событий календаря **на завтра**. Из названий событий вычищаются аудитории, скобки и пометки вроде «лек.», «лб.», «пр.», повторы убираются. Если на завтра событий нет, пункт не появляется.

Это удобно, если вы ведёте расписание занятий в календаре. Если календарь для вас — просто встречи, оставьте `false`.

## Вёрстка на нестандартном экране

Все отступы и размеры шрифтов в интерфейсе заданы в «базовых» координатах 600×1024. При отрисовке приложение считает масштаб:

```
масштаб = min(ширина_экрана / 600, высота_экрана / 1024)
```

То есть на экране другого размера картинка пропорционально увеличивается или уменьшается, сохраняя пропорции макета. Это лучше, чем жёсткая привязка, но есть нюансы:

| Что не так | Что сделать |
|---|---|
| Интерфейс выглядит мелко или крупно | поменяйте `DESIGN_WIDTH` / `DESIGN_HEIGHT` под свой экран: например, для 800×1280 поставьте `800` и `1280` |
| Планшет 4:3 (например, 768×1024) | попробуйте `DESIGN_WIDTH = 600`, `DESIGN_HEIGHT = 800`, чтобы контент занял больше места по высоте |
| Огромные пустые поля сверху и снизу | экран шире макета — уменьшите `DESIGN_HEIGHT` или добавьте отступы в `DashboardView` |
| Текст обрезается или наезжает | скорее всего, шрифт не влез в свою строку — правьте размеры в `DashboardView` под конкретный блок |
| Совсем другой экран (телефон, квадратный дисплей, альбом) | проще переделать макет через нейросеть: [PROMPT_RU.md](../../PROMPT_RU.md) |
| Планшет закреплён «вверх ногами» | ничего делать не нужно: приложение само поворачивает отрисовку на 180° по акселерометру |

Помните: альбомная ориентация в приложении отключена. Если экран физически горизонтальный, панель всё равно будет рисоваться в портретной логике.

### Как попросить нейросеть переделать вёрстку

1. Откройте [PROMPT_RU.md](../../PROMPT_RU.md) и скопируйте его целиком — это подробное задание со всеми правилами проекта.
2. Приложите файлы: `app/src/ru/home/dashboard/DeviceConfig.java`, `DashboardView.java`, `PackingOverlayView.java` и `AndroidManifest.xml`.
3. Приложите скриншот вашего экрана или укажите разрешение и плотность.
4. Попросите внести минимальные правки и объяснить, что изменилось.
5. Соберите APK по [BUILD.md](BUILD.md) и проверьте по чек-листу ниже.

## Сборка и проверка

После правки `DeviceConfig.java` (и любых файлов вёрстки):

```powershell
powershell -ExecutionPolicy Bypass -File .\build\build.ps1
powershell -ExecutionPolicy Bypass -File .\build\build.ps1 -Install
```

Что проверить на своём устройстве после адаптации:

- [ ] панель открылась, текст читается, ничего не обрезано;
- [ ] город подписан правильно, погода совпадает с реальной;
- [ ] дата и время правильные — проверьте часовой пояс;
- [ ] события календаря показывают верное время;
- [ ] экран включается и гаснет в заданные часы (можно проверить через `scripts\dashboard.ps1` или временно поменять часы на ближайшие);
- [ ] вечерний список появляется в `PACKING_HOUR` и не появляется в субботу, если так задумано;
- [ ] кнопки **≡** и **⏻** работают;
- [ ] после перезагрузки панель запускается сама;
- [ ] при перевороте планшета картинка читается правильно.

Если что-то не сходится — [FAQ](FAQ.md), [TESTING.md](TESTING.md) и [LIMITATIONS.md](LIMITATIONS.md). И честное напоминание: кроме вашего планшета это никто не проверит.
