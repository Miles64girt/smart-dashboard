# Архитектура и приватность

Как устроено приложение изнутри: классы, поток данных, расписание, кэш, разрешения и почему здесь нет ни одной сторонней библиотеки.

> ⚠️ **Проверено только на одном планшете.** Архитектура описана по коду версии 1.3 и опыту эксплуатации на Huawei MediaPad T3 7 (BG2-U01), Android 7.0. На других устройствах поведение системы может отличаться. Используете на свой риск, см. [TESTING.md](TESTING.md).

## Общая картина

```
MainActivity (один экран, без фрагментов)
 ├─ DashboardView          — вся панель на Canvas: две половины 50/50
 ├─ PackingOverlayView     — вечернее окно поверх панели
 │   └─ PackingListModel  — пункты списка + отметки
 ├─ WeatherRepository ──→ wttr.in / Open-Meteo ──→ WeatherData
 │   └─ ClothingAdvisor   — рекомендации по одежде
 ├─ CalendarRepository ──→ CalendarContract ──→ EventItem
 ├─ Scheduler / ScheduleReceiver — будильники 08:00 / 20:00 / 21:00
 ├─ BootReceiver           — автозапуск после перезагрузки
 ├─ OrientationWatcher    — переворот портрета по акселерометру
 └─ PowerAccessibilityService — системное меню питания
```

Всё приложение — это одна Activity, два собственных View, несколько репозиториев и пара ресиверов. Нет фрагментов, навигации, базы данных и фоновых служб (кроме опциональной службы доступности). Активность живёт на экране, а расписание держится на системных будильниках — поэтому расход энергии минимальный.

## Компоненты

| Класс | Ответственность |
|---|---|
| `MainActivity` | жизненный цикл экрана, полноэкранный режим, яркость, день/ночь, разрешения, обновление данных, обработка event-ов кнопок |
| `DashboardView` | вся отрисовка панели на `Canvas`: дата, город, погода, иконка, детали, «Что надеть», карточки событий, кнопки; поворот на 180° |
| `PackingOverlayView` | вечернее окно: размытый фон, карточка, чек-лист, добавление пунктов, анимация успеха и салют |
| `PackingListModel` | список пунктов на день, отметки, сохранение своих пунктов, «Тетрадь» из календаря |
| `PackingItem` | одна строка списка: идентификатор, текст, признак «свой», отметка |
| `WeatherRepository` | загрузка JSON с wttr.in, резервный запрос к Open-Meteo, HTTP-таймауты |
| `WeatherData` | разбор ответа, коды погоды, описание условий, кэш в JSON |
| `ClothingAdvisor` | правила «что надеть» по ощущаемой температуре, ветру и осадкам |
| `CalendarRepository` | чтение событий на сегодня через `CalendarContract.Instances` |
| `EventItem` | событие: название, описание, начало, конец, признак «весь день» |
| `Scheduler` | постановка ежедневных будильников 08:00 / 20:00 / 21:00 |
| `ScheduleReceiver` | обработка срабатывания будильника: разбудить экран, включить ночной режим или открыть список |
| `BootReceiver` | восстановление расписания и запуск панели после перезагрузки |
| `OrientationWatcher` | определение физического переворота планшета по акселерометру |
| `PowerAccessibilityService` | показ системного меню питания по кнопке ⏻ и ничего больше |
| `BlurUtil` | размытие снимка панели для фона вечернего окна (RenderScript) |
| `Prefs` | локальные настройки и кэш: погода, город, отметки списка, состояние переворота |
| `TimeUtil` | единый часовой пояс: из `DeviceConfig` или системный |
| `DeviceConfig` | все настройки проекта: город, пояс, расписание, яркость, вещи, вёрстка |

## Поток данных

### Старт приложения

1. `MainActivity` создаёт `DashboardView` и `PackingOverlayView`, включает полноэкранный режим и `FLAG_KEEP_SCREEN_ON`.
2. Из `Prefs` поднимается последний кэш погоды — панель показывает данные сразу, ещё до сети.
3. Если сохранено состояние переворота, отрисовка сразу разворачивается на 180°.
4. Планируются будильники расписания.
5. Запрашивается разрешение `READ_CALENDAR`, если его ещё нет.
6. Сразу запускаются обновление погоды и календаря; при `BOOT_COMPLETED` дополнительно зажигается экран.

### Цикл обновления

Раз в 30 секунд `Handler` перерисовывает часы и дату и проверяет, не устарели ли данные:

| Данные | Максимальный возраст | Обновление |
|---|---|---|
| Погода | 30 минут | `wttr.in`, при ошибке — Open-Meteo, при отсутствии сети — кэш |
| Календарь | 5 минут | локальный `CalendarContract`, работает без сети |
| Дата, часы, день/ночь | 30 секунд | перерисовка `Canvas` |

При появлении сети (`CONNECTIVITY_ACTION`) данные обновляются немедленно, не дожидаясь таймера.

### Сеть и кэш

- Основной источник — **wttr.in** (`?format=j1`): бесплатно, без ключа, отдаёт текущую погоду, прогноз на сегодня, восход/закат и город одним JSON.
- Резервный — **Open-Meteo**: используется только когда координаты заданы явно (`AUTO_LOCATION = false`). При автоопределении города координат нет, и резерв мог бы показать погоду другого места, поэтому в этом режиме он не вызывается. На сети тестового планшета Open-Meteo был недоступен (TCP-таймаут на уровне провайдера).
- Коды погоды WorldWeatherOnline переводятся во внутренние коды WMO, чтобы иконки, описания и рекомендации по одежде считались единообразно.
- Успешный ответ сохраняется в `SharedPreferences` как JSON вместе со временем загрузки и названием города. Без сети показывается кэш и пометка «Нет сети · данные ЧЧ:ММ».
- При ошибках действует защита от частых повторов: пауза 1 → 2 → 4 → 8 → 16 → 30 минут, не больше.

### Автоопределение города

В версии 1.3 при `AUTO_LOCATION = true` приложение запрашивает у wttr.in прогноз без координат (`https://wttr.in/?format=j1`) и берёт город из ответа — wttr.in определяет его по IP. Название города сохраняется в настройках и показывается в углу панели; при следующем запуске подпись берётся из кэша. Если автоопределение выключено, используются `LATITUDE`, `LONGITUDE` и `CITY` из `DeviceConfig`.

### Календарь

- Чтение идёт через официальный `CalendarContract.Instances` — системное API Android, без OAuth-библиотек и без доступа к аккаунту Google.
- Диапазон — с 00:00 до 24:00 текущего дня в часовом поясе приложения.
- Сортировка по времени начала, максимум 12 событий; события «весь день» показываются отдельной меткой «ВЕСЬ ДЕНЬ».
- Если событий нет или разрешение не выдано — правая половина просто не рисуется.
- При чтении названия и описания не изменяются; для «Тетради» из названий событий дополнительно вычищаются аудитории, скобки и типы занятий.

### Экран и режимы

- **День:** включён `FLAG_KEEP_SCREEN_ON`, яркость окна `DAY_BRIGHTNESS` (по умолчанию 0,62), экран не гаснет.
- **Ночь:** флаг сна снимается, яркость окна падает до `NIGHT_BRIGHTNESS` (0,02), поверх рисуется затемнение и подпись «касание — включить экран». По системному таймауту экран гаснет.
- **Касание ночью:** включается экран и дневной режим на 5 минут, затем режим возвращается по расписанию.
- Яркость задаётся через `WindowManager.LayoutParams.screenBrightness` — системные настройки не меняются.

## Расписание

| Время (по поясу приложения) | Что происходит |
|---|---|
| `DAY_START_HOUR` (08:00) | `AlarmManager.setExactAndAllowWhileIdle` → `ScheduleReceiver` → `WakeLock(ACQUIRE_CAUSES_WAKEUP)` → экран включается, панель на экране |
| `PACKING_HOUR` (20:00) | открывается вечерний список, кроме субботы (если не отключено в конфиге); если всё уже отмечено — пропускается |
| `DAY_END_HOUR` (21:00) | ночной режим, снятие `KEEP_SCREEN_ON`, приглушённая яркость, затемнение |
| каждый старт и перезагрузка | будильники ставятся заново на ближайшие сутки |

Будильники точные (`RTC_WAKEUP`), поэтому срабатывают и в Doze — но только если прошивка не «замораживает» приложение полностью. На прошивках Huawei/EMUI нужно разрешить автозапуск, иначе будильники и старт после перезагрузки могут не работать.

## Вечерний список вещей

- Отдельный слой `PackingOverlayView` поверх панели. При показе снимается снимок `DashboardView`, уменьшается в 4 раза, размывается RenderScript (радиус 18) и затемняется — так окно получает размытый фон панели.
- `PackingListModel` собирает пункты: стартовые из `DeviceConfig.DEFAULT_PACKING_ITEMS` (по умолчанию пусто), свои из `SharedPreferences`, опционально «Тетрадь» из событий календаря на завтра.
- Отметки хранятся с ключом по дате: новый день — чистый список, свои пункты остаются. Флаги «показано сегодня» и «всё отмечено» не дают окну открываться повторно в тот же день.
- Тап — переключение отметки; долгое нажатие (больше ~0,65 с) на свой пункт — удаление.
- Когда отмечено всё: зелёная галочка, надпись «Всё собрано!» / «Можно ложиться спать», салют из частиц, автозакрытие примерно через 5,6 секунды.

## Переворот экрана

Манифест фиксирует портретную ориентацию — система никогда не поворачивает дисплей. Переворот «вверх ногами» определяет `OrientationWatcher` по акселерометру: фильтр нижних частот, порог 4 м/с² и удержание 500 мс отсекают тряску. При перевороте `DashboardView` поворачивает `Canvas` на 180°, поэтому панель и вечернее окно читаются правильно. Состояние запоминается и применяется сразу при следующем запуске.

Почему не системный `sensorPortrait`: прошивка тестового планшета его игнорировала, а собственный поворот отрисовки работает одинаково независимо от прошивки. Ограничение: при горизонтальном положении планшета поворот вокруг вертикальной оси акселерометром не определить — нужен гироскоп, которого на тестовом устройстве нет.

## Разрешения и приватность

| Разрешение | Зачем | Что приложение **не** делает |
|---|---|---|
| `INTERNET` | загрузка прогноза погоды | не отправляет никакой другой информации |
| `ACCESS_NETWORK_STATE` | проверка, есть ли сеть | — |
| `READ_CALENDAR` | чтение событий на сегодня | не пишет и не удаляет события, не читает чужие календари без доступа |
| `WAKE_LOCK` | включение экрана по будильнику | не держит процессор разбуженным постоянно |
| `RECEIVE_BOOT_COMPLETED` | автозапуск после перезагрузки | — |
| `MODIFY_AUDIO_SETTINGS` | беззвучный режим при старте | не записывает звук |
| Служба доступности (опционально) | показать системное меню питания | не читает содержимое экрана, не нажимает кнопки, не следит за вводом |

Ключевые принципы:

- **Нет паролей и токенов.** Приложение не просит пароль Google, не хранит OAuth-токены и не требует входа куда-либо. Календарь читается через системный API — доступ к аккаунту даёт сама ОС.
- **Погода — единственные внешние данные.** На wttr.in уходят только координаты или название города; никаких аккаунтов, ключей и идентификаторов.
- **Всё локально.** Настройки, кэш погоды, список вещей и отметки лежат в `SharedPreferences` приложения. `allowBackup="false"` — данные не уезжают в облачный бэкап.
- **Сеть только по HTTPS.** Запросы идут на два известных домена погоды, закреплённых в `network_security_config.xml`. Очищенный HTTP запрещён.
- **Разрешения по минимуму.** Нет доступа к контактам, звонкам, SMS, местоположению, камере, микрофону, файлам.
- **Никакой аналитики.** Никаких SDK, сбора статистики, рекламы и трекеров.

## Почему без библиотек

| Альтернатива | Почему не используется |
|---|---|
| AndroidX / AppCompat / RecyclerView | лишние мегабайты памяти и инициализация ради одного экрана |
| Jetpack Compose | тяжёлый рантайм, требователен к GPU и памяти — плохо для 1 ГБ ОЗУ |
| OkHttp / Gson | в Android уже есть `HttpURLConnection` и встроенный `org.json` |
| Google Play Services Auth | GMS на старом планшете устарел; календарь доступен через `CalendarContract` без GMS-логина |
| Gradle | сотни мегабайт ради одной сборки; ручной `aapt2` → `javac` → `d8` быстрее и прозрачнее |

Отсюда же решение рисовать интерфейс одним `View` на `Canvas`: нет XML-разметки, картинок и анимационных фреймворков. Иконки погоды, кнопки и салют тоже нарисованы кодом. Это даёт около 12 МБ PSS и мгновенную отрисовку на слабом процессоре.

## Сборка без Gradle

```
aapt2 compile   — компиляция ресурсов (res/)
aapt2 link      — сборка ресурсов с манифестом, генерация R.java
javac           — компиляция Java-исходников против android.jar (API 24)
d8              — перевод байткода в classes.dex (min-api 24)
zipalign        — выравнивание APK
apksigner       — подпись ключом build/keystore.jks и проверка подписи
```

Сборка идёт во временном ASCII-каталоге вне репозитория (по умолчанию `%TEMP%\smart-dashboard-build\work`, можно задать через `-StageRoot`), потому что `aapt2` не переваривает кириллицу в путях. Ключ подписи генерируется локально при первой сборке и в репозиторий не попадает — подробности в [BUILD.md](BUILD.md).

## Особенности Android 7.0

| Особенность | Как обходится |
|---|---|
| Android 7.0 не доверяет корням Let's Encrypt (ISRG Root X1/X2) — они появились в 7.1.1 | официальные корни ISRG добавлены в `res/raw` и подключены **только** к доменам погоды в `network_security_config.xml`; системное доверие не ослаблено |
| Системный часовой пояс планшета может быть сломан или «залип» | часовой пояс задаётся в `DeviceConfig.TIME_ZONE`; пусто — используется системный |
| Точные будильники в Doze могут откладываться | `setExactAndAllowWhileIdle`, а также исключение приложения из оптимизации батареи |
| Фоновый запуск активности на новых Android строже | проект рассчитан на Android 7.0; на Android 10+ автозапуск может вести себя иначе — проверяйте на своём устройстве |
| RenderScript устарел, но есть в API 24 | используется только для одного размытия при показе списка |
